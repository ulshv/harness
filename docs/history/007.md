# 007. `testing-wms-mcp`: an MCP server over the warehouse API

**Status:** done, in review

## Goal

Hand the warehouse to any agent as MCP tools: a thin adapter over the `testing-wms` REST API, and the template for
"MCP for any API". Step 2 of 4: API (006) → **MCP server** → MCP client in harness (008) → evals (009).

## What was added

- `services/testing-wms-mcp` on `mcp` 2.3.0: `MCPServer` with eight tools in `app/server.py`, a thin `Wms` client in
  `app/wms.py` (API body verbatim on success, `ToolError` on failure), `create_app()` with a Host/Origin allowlist
  and `/health`. Port 8101 in compose, waits for `testing-wms` to be healthy.
- 19 tests: tools over an in-memory `Client(server)` with a mocked API, and the HTTP app's allowlist.

## Concepts

- **MCP is a thin adapter.** A tool's docstring is its description and its type hints are its input schema: that
  is everything the model knows about it. Descriptions state facts; policies stay in the agent's prompt.
- **`ToolError` is the model's channel.** Its message reaches the model as `is_error: true`; any other exception
  is sanitized to a generic failure.
- **Two protocol eras.** `mcp` 2 speaks revision 2026-07-28 (no handshake, no sessions) and still serves 2025-era
  clients through `initialize`. harness stays on 1.x because `langchain-mcp-adapters` requires `mcp<2`.
- **DNS-rebinding protection.** `streamable_http_app()` defaults to a localhost-only `Host` allowlist; another
  container's call gets 421 `Invalid Host header`, which the client reports only as a transport error.

Smoke run before review, on throwaway containers in a private network with the compose service names:

- `mcp` 2 `Client("http://testing-wms-mcp:8101/mcp")` from inside the network: protocol `2026-07-28`, 8 tools,
  the partial reserve and the 503 as above.

## Debrief: takeaways

Opus review of the staged diff. Fixed after review:

- **Path traversal through `sku`.** `f"/stock/{sku}"` went out unescaped: a model-made `../_state` reached the test
  panel the MCP server promises not to expose, `../orders/1003` returned an order. `quote(sku, safe="")` keeps it one
  segment, and the API answers 404.
- **A 422 reached the model as raw pydantic JSON**; now it reads the first error's `msg`. An empty error body says
  `HTTP <status>` instead of nothing, and decoding errors count as "unreachable" (`RequestError`, not only
  `TransportError`).
- **`move_stock`'s description** now says the locations must differ and that it returns this SKU's stock only.
- **Tests added:** escaping, a 422 list `detail`, `list_orders` without a status, and one stateless `tools/call`
  over HTTP with no `initialize` first, the path harness takes in 008.
