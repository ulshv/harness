# 006. `testing-wms`: a warehouse API for evals

**Status:** done, reviewed
**Commit:** `5d61d6a`

## Goal

Give future evals an external system with known truth: a small in-memory warehouse API with seeded traps and a
reset/state panel. Step 1 of 4: API → MCP server (007) → MCP client in harness (008) → evals (009).

## What was added

- `services/testing-wms`: FastAPI, `store.py` (warehouse logic) behind thin routes in `api.py`, one pydantic `Store`
  for the seed, the state and `/_state`; `seed.jsonc` with a comment on every trap. Port 8100 in compose.
- Reserve / cancel / move with API invariants (404/409/503); partial reservation allowed so the agent's policy is
  measurable.
- `make test` / `make lint` run for every service. 19 new tests (64 total).

## Concepts

- **Reserved stock is derived, not stored**: the sum of order allocations, so reserve/cancel touch one place.
  `computed_field` puts a line's `reserved` into every dump without accepting it as input.
- **`async def` as a lock**: handlers run one at a time on the event loop thread; correct only with one worker.
- **Response model as a filter**: `/products` returns `StoredProduct` but declares `list[Product]`, so the
  test-only `broken` flag never leaves the API.

## How to verify

```bash
make test && make lint
make up    # restart it: compose watch doesn't pick up a new service
curl -s -X POST localhost:8100/orders/1003/reserve | jq '{status: .order.status, shortages}'
# {"status": "partially_reserved", "shortages": [{"sku": "TAPE-48", "missing": 5}]}
curl -s -w ' %{http_code}\n' localhost:8100/stock/SCN-01      # 503
curl -s -X POST localhost:8100/_reset >/dev/null && curl -s localhost:8100/orders/1003 | jq .status   # "new"
```

## Debrief: takeaways

Opus review of the staged diff. Fixed after review:

- **Re-reserve duplicated allocations.** After another order freed stock, a second reserve appended a new
  allocation for a location the line already had, out of id order. Sums stayed right, but an exact `/_state` in
  evals would not. Now it tops up the existing one and keeps allocations sorted; a store test covers it (the seeds
  can't reach this path).
- **An unmapped domain error** would have raised `KeyError` inside the exception handler; it is a 500 now.
- **Wrong mechanism in a comment**: FastAPI keeps the `StoredProduct` instance and drops `broken` when it serializes
  with the response model's schema, not by re-validating.
