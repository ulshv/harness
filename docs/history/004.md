# 004. `error` and `done` events

**Status:** done, reviewed
**Commit:** —
**Spec:** [specs/004](../specs/004_stream-error-done-events.md) · **Arch:** [arch/001](../arch/001_chat-request-flow.md) (updated)

## Goal

Every `/chat/stream` ends with exactly one terminal event, `done` or `error`, so a client can tell a
finished answer from a dead stream. `/chat/invoke` uses the same contract.

## What was added

- `app/api/chat/outcome.py`: `append_error_or_done` stage (before batching), `error_event`, and an error
  table of langchain-core's provider-neutral errors looked up by MRO (`llm_rate_limited`, `llm_unavailable`,
  `recursion_limit`, `internal`).
- `DoneEvent` / `ErrorEvent` (with `ErrorCode` as a `Literal`) in the `ChatEvent` union.
- `/chat/invoke`: `200` with `done` as the last event, or `500` with the `ErrorEvent` body (documented in OpenAPI).
- `app/agent/graph.py`: `RECURSION_LIMIT = 25`, applied with `compile().with_config(...)`.
- Tests: `StreamingFakeModel` in `conftest.py` (the suite's first streaming fake), `test_outcome.py`,
  and stream/invoke error paths. 35 tests total.

## Concepts

- **A pipeline stage for error handling**: `try/except` around `async for` inside a generator turns an exception
  into a final event. Its position before batching flushes buffered text before `error` without extra code.
- **`Exception` vs `BaseException`**: `CancelledError` (client disconnect) and `GeneratorExit` aren't
  `Exception`s, so cancellation passes through untouched.
- **MRO lookup** instead of an `isinstance` chain: `next(table[c] for c in type(exc).__mro__ if c in table)`,
  so the most specific class wins.
- **Safe errors**: the client gets a code plus a fixed message; the exception goes to the log only.
- **`response_model` + returning a `Response`**: a returned `JSONResponse` bypasses `response_model`, so the
  success schema is declared explicitly and the `500` via `responses=`.

## How to verify

```bash
make test && make lint                       # 35 passed
curl -sN localhost:8000/chat/stream -H 'content-type: application/json' -d '{"message":"hi"}' | tail -3
# event: done / data: {}
curl -s localhost:8000/chat/invoke -H 'content-type: application/json' -d '{"message":"hi"}'
# {"events":[{"type":"text",...},{"type":"done"}]}
# error path without touching the dev loop: a second server with a wrong key
cd services/harness && set -a && . ../../.env && set +a
LLM_API_KEY=wrong uv run uvicorn app.main:app --port 8001 &
curl -sN localhost:8001/chat/stream -H 'content-type: application/json' -d '{"message":"hi"}'
# event: error / data: {"code":"internal","message":"Internal error."}   (a 401 is our config, not the provider's outage)
curl -s -w '\n%{http_code}\n' localhost:8001/chat/invoke -H 'content-type: application/json' -d '{"message":"hi"}'
# {"type":"error","code":"internal",...} / 500
kill %1
```

Live run: success ends with `done`; with a wrong key the log shows `chat run failed` + `AuthenticationError: 401`,
the client sees only the code and message, and the key never appears in the log.

## Gotchas

- **LangGraph 1.2.15 default `recursion_limit` is 10007** (`DEFAULT_RECURSION_LIMIT`), not 25 as in
  older versions. Without an explicit limit `recursion_limit` is practically unreachable.
- **`add_messages` mutates messages**: it sets `id` on the passed object in place, and adding the same
  object again *replaces* it instead of appending. A fake model that returns the same `AIMessage` object
  twice silently ends the ReAct loop. Test fakes need fresh message objects per call (`call_tool()` factory).
- `langchain-openai` re-raises every provider error as its own subclass that inherits **both** the `openai`
  SDK type and a provider-neutral `langchain_core.exceptions.Model*Error` (`ModelRateLimitError`,
  `ModelAPIError`, `ContextOverflowError`, …, each with `is_retryable`). Key error handling on the
  langchain-core classes. Note that `ModelRateLimitError` and `ModelAPIError` are siblings, not parent and child.
- `langchain-core` fires `on_llm_new_token` for every chunk `_astream` yields, so a fake's `_astream` must
  not call `run_manager` itself, or tokens double.

## Questions

1. Why does a disconnected client produce no `error` event?
   <details><summary>Answer</summary>Disconnect cancels the task, which raises `CancelledError` inside the generator. It's a `BaseException`, not an `Exception`, so `except Exception` doesn't catch it, and nobody is listening anyway.</details>
2. Why does a wrong API key produce `internal` and not `llm_unavailable`?
   <details><summary>Answer</summary>A 401 is our configuration problem, and a retry won't fix it. `llm_unavailable` tells the user to try again later, which would be a lie. Only retryable provider conditions (5xx, connection, timeout) are `llm_unavailable`.</details>

## Debrief: takeaways

Opus review of the staged diff. Fixed after review:

- **Provider 4xx said "try again later".** The table keyed on `openai.APIError`, so bad key, unknown model,
  400 and context overflow all became `llm_unavailable`. It now keys on langchain-core's provider-neutral
  errors, and only retryable ones (`ModelAPIError`, `ModelConnectionError`, `ModelTimeoutError`,
  `ModelRateLimitError`) are `llm_*`; everything else is `internal`.
- **Recursion numbers in comments were off.** Measured: 25 allows 11 tool rounds plus the answer, and 12 rounds
  raise. The test comment wrongly called 25 "the default".
- **The `/invoke` comment gave the wrong reason** for `response_model`. Actually FastAPI can't infer one from
  the `ChatResponse | JSONResponse` annotation.
- **Added test:** an error before any event gives a lone `error` with status 200.

Documented, not fixed:

- **Interrupts will end with `done`.** The root graph swallows `GraphInterrupt` and emits `__interrupt__`. This
  needs an `interrupt` terminal event in the step that adds human-in-the-loop (spec non-goals, roadmap backlog).
- **Logging rides `logging.lastResort`** (no level or time) until roadmap step 9.
- **The terminal-event guarantee covers the graph and the translator**, not batching or encoding.
- **Context overflow is `internal` for now.** It likely deserves its own code once memory (step 3) makes it common
  (roadmap backlog).
