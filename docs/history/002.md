# 002. Production layout for harness: layers, typed SSE contract, fail-fast config

**Status:** done, reviewed
**Commit:** `6fc04b5`

## Goal

Turn the step 1 PoC into code that can grow: thin HTTP layer, the LangGraph → events
translation isolated and flat, typed event contract, config validated at startup.

- Ruff lint baseline: `I`, `UP`, `B`, `SIM` on top of defaults.
- `ToolCall` / `ToolResult` now carry ids (`id`, `tool_call_id`), so a UI can pair a call with its result.

## Concepts

- **App factory + lifespan**: `create_app(graph_factory)` lets tests inject a fake graph without
  `dependency_overrides`; the real graph is built in `lifespan`, so a bad `.env` fails the boot instead of the first request.
- **`app.state` + `Annotated` dependency**: `Graph` is a reusable type alias; routes just declare `graph: Graph`.
- **Dispatch instead of nesting** in `stream.py`: a table by stream mode (`messages` → tokens,
  `updates` → finished messages) and `functools.singledispatch` by message type (`AIMessage` → tool calls,
  `ToolMessage` → result). A new event kind = one new function, not one more indentation level.
- **`astream(..., version="v2")`** yields typed `StreamPart` dicts (`type`, `ns`, `data`) instead of bare tuples.
- **`SecretStr`**: the key never shows up in `repr`, logs or tracebacks; `ChatOpenAI` accepts it as is.
- **`ClassVar` on pydantic models**: the SSE event name lives on the class but stays out of the JSON payload.

## Gotchas

- Two `docker compose up --watch` on the same project fight: the second `--build` recreates the container

  `kill -9` (SIGINT/SIGTERM makes compose stop the containers).

## Debrief: takeaways

Opus review of the staged diff. Fixed before commit:

- `_from_updates` assumed every node output is `{"messages": [...]}`. Real "updates" payloads can be `None`
  (no writes), a list (several writes), a single message, or `__interrupt__` / `__metadata__`.
  Now a `match` in `_written_messages` handles each shape; covered by `test_stream.py`.
- `LLMSettings` only rejected an empty key; `LLM_BASE_URL=""` / `LLM_MODEL=""` booted fine and failed
  on the first request. Now `base_url: HttpUrl`, `model` has `min_length=1`.
- A comment in `main.py` claimed lifespan "touches the LLM"; it only reads env and builds a client.

Deferred, next step candidates:

- **Errors mid-stream look like success**: headers (200) are already sent, so an LLM/tool failure or
  `GraphRecursionError` just ends the stream. Needs typed `error` + `done` events.
- **No streaming-fake test**: the fake model doesn't stream, so token dedup for real streaming models is
  verified by hand only. Add a streaming fake together with the error path.
- **Client disconnect** is noticed only on the next send (the 15 s keepalive ping at worst), so a long
  LLM/tool call keeps burning tokens. Revisit before long tools/subagents.
- `ToolResult.content` uses `msg.text` and drops non-text blocks (MCP images); `invalid_tool_calls`
  aren't surfaced. Revisit at step 8 (MCP).
