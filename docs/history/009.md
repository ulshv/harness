# 009. MCP tools in harness

## Goal

Give the agent the warehouse: tools from configured MCP servers join its built-in ones at startup. Step 3 of 4:
API (006) → MCP server (007) → **MCP client in harness** → evals (010); the first slice of roadmap step 8.

## What was added

- `MCP_SERVERS` (`McpSettings`): a JSON map of server name → URL; names are `^[a-z][a-z0-9_]{0,15}$`, so the
  prefixed tool names stay valid for providers. compose wires `{"wms": "http://testing-wms-mcp:8101/mcp"}` and
  harness waits for the MCP server to be healthy.
- `app/agent/mcp.py`: loads tools per server via `langchain-mcp-adapters` 0.3.2, prefixed (`wms_get_order`); a dead
  server is skipped with a warning. The graph factory is async now.
- `build_graph(model, tools)`; `ToolNode(handle_tool_errors=handle_tool_errors)` from `app/agent/errors.py`: a
  crashing tool becomes a fixed error text for the model, the traceback goes to the log, and the run goes on.
- `tool_result.status`: `"success"` or `"error"`, from `ToolMessage.status`.
- 9 new tests (57 in harness).

## Concepts

- **MCP tools are ordinary LangChain tools** once loaded: the adapters wrap each one as a `StructuredTool` whose
  call opens an MCP session. The model sees name, description and schema, nothing MCP-specific.
- **Failure has three layers.** An MCP `is_error` result (the server's `ToolError`) is a normal tool result with
  `status="error"`; a crash inside the tool call (server down) is caught by `ToolNode`'s handler; a server down at
  startup is skipped. None of them ends the run.
- **`ToolNode` reads the handler's annotation** to decide what it catches; `Exception` means every tool failure.

## How to verify

```bash
make test && make lint
make up    # restart it: harness now waits for testing-wms-mcp
chat() { curl -sN localhost:8000/chat/stream -H 'content-type: application/json' -d "$1"; }
chat '{"message":"Can we fully reserve order 1003? Do not reserve anything, just check.","thread_id":"wms"}'
docker compose stop testing-wms-mcp
chat '{"message":"How much WRAP-500 is in stock?","thread_id":"wms"}'
```

Smoke run before review, on a throwaway stack (testing-wms, testing-wms-mcp, harness with the real model):

- "Can we fully reserve order 1003?": `wms_get_order`, then two `wms_get_stock` in parallel, then a table: gloves
  fine, TAPE-48 short by 5, nothing reserved.
- "Which of its products is short?" on the same thread: answered from history, no tool calls.
- MCP server stopped, "How much WRAP-500 is in stock?": seven tool calls, each `tool_result` with `status: "error"`
  and the fixed text (then "…its service is unavailable.", reworded after review); the agent said the warehouse is unavailable and didn't guess; the stream ended with `done`.

## Knobs

| Knob | Where | What you'll see |
|---|---|---|
| `MCP_SERVERS` | `compose.yaml` / env | another server's tools under its prefix; a bad name or URL fails startup |
| `TOOL_FAILED` | `agent/errors.py` | the text the model reads when a tool crashes |
| `MCP_TIMEOUT_SECONDS` | `agent/mcp.py` (a constant) | the longest an MCP server may stay silent, per connect and per read; a slow tool that sends nothing for longer fails with `TOOL_FAILED` |
| a server down at startup | `docker compose stop testing-wms-mcp`, then restart harness | a warning, and the agent has no `wms_*` tools |

## Debrief: takeaways

Opus review of the staged diff. Fixed after review:

- **A hung MCP server could stall harness for minutes.** The adapters wait 30 s to connect and 5 minutes for a
  response; servers load one at a time, so startup (and `/health`) would hang, and every call to such a server
  would hold the stream open. Every connection now gets a 15 s `timeout` and `sse_read_timeout` (the
  `MCP_TIMEOUT_SECONDS` constant in `agent/mcp.py`); it applies to loading and to every tool call, per read.
- **The loader test didn't check the loader's two rules.** The fake now asserts the URL is a `str` and
  `tool_name_prefix` is on: going back to an `HttpUrl` passes every other test but breaks at runtime, hidden as a
  "dead server".
- **A bad `.env` failed only after the MCP wait**; LLM settings load first now.
- **`TOOL_FAILED`** said "its service is unavailable" for any crash, local bugs included; it says "The tool failed to
  run." now. Two comments were sharpened (`handle_tool_errors`'s default-handler note, `ServerName`'s validity claim).
