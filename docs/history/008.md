# 008. Conversations by `thread_id`

**Status:** done, reviewed
**Commit:** `74ef451`
**Spec:** [specs/008](../specs/008_conversation-thread.md) · **Arch:** [arch/001](../arch/001_chat-request-flow.md) (updated) · branch `feat/testing-mcp`

## Goal

Let the agent remember a conversation: the client names a thread, harness keeps it in memory. The first slice of
roadmap step 3.

## What was added

- `ChatRequest.thread_id`: optional, 1–64 of `[A-Za-z0-9_-]`; omitted → a fresh UUID per request (`default_factory`).
- `build_graph` compiles with `InMemorySaver`; `chat_events` passes `thread_id` in the run config.
- `FakeToolModel` records what each call was sent. 3 new tests (48 in harness).

## Concepts

- **Checkpointer**: saves the graph state after every step under a `thread_id`; the next run on that thread starts
  from it. The input is only the new message; `add_messages` appends it to the restored history.
- **What's saved is what nodes return.** The system prompt is prepended per LLM call and never stored, so it isn't
  duplicated per turn, and a changed prompt applies to old conversations on their next turn.
- **Unanswered tool calls** break a thread: providers require every tool call to be answered right after it.
  Nothing in our stack repairs that except deepagents' `PatchToolCallsMiddleware`; we accept the limit until step 4.

## How to verify

```bash
make test && make lint
chat() { curl -sN localhost:8000/chat/stream -H 'content-type: application/json' -d "$1"; }
chat '{"message":"My name is Sergey.","thread_id":"demo"}'
chat '{"message":"What is my name?","thread_id":"demo"}'   # …Sergey…
chat '{"message":"What is my name?"}'                      # a fresh thread: it doesn't know
```

Live run before review (hot reload on the running dev loop): thread `demo-008` answered "Sergey"; the same
question without `thread_id` answered "unknown". OpenAPI shows `thread_id` as an optional string with the pattern.

## Knobs

| Knob | Where | What you'll see |
|---|---|---|
| `thread_id` | request body | same id → the dialog continues; a new id → a clean conversation |
| `checkpointer=` | `agent/graph.py` | remove it → every request forgets (and `thread_id` is ignored) |

## Debrief: takeaways

Opus review of the staged diff. Fixed after review:

- **No test guarded "the second turn doesn't replay history".** It held by hand; now the second turn's events are
  asserted as literals (`text`, `done`).
- **Memory was understated.** `InMemorySaver` keeps every checkpoint, a full history copy per step, so a thread
  grows roughly with the square of its turns, and requests without `thread_id` now leave threads behind. Documented
  in the spec, arch and ROADMAP, with the small fix (delete anonymous threads after the run) and its trigger.
- **Test hazard noted:** `FakeToolModel` returns the same reply objects as it cycles; on a thread a repeated reply
  replaces the saved message instead of appending. Comment added.
