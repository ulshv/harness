## 010.1. Text stream in the browser

### What was added

- `services/webapp`: Vite 8.3 + React 19.3 + TypeScript 6.0 + Tailwind 4.3, layered as `api/` → `chat/` →
  `containers/` / `components/` → `pages/`.
- `streamChat()`: SSE over a `fetch` POST, parsed by `eventsource-parser`; event types generated from harness's
  OpenAPI (`make api-types`).
- `chat/turn.ts`: `applyEvent` folds events into a turn (text only for now), `closeTurn` ends a turn that got no
  `done`/`error`. Send is disabled while the last turn streams.
- Design tokens in `index.css` with the default palette reset; dark mode from `prefers-color-scheme`.
- compose service `webapp` on `127.0.0.1:8080`, Vite proxies `/api/*` to harness; `make test` / `make lint`
  include the webapp (10 tests; oxlint, Prettier, `tsc -b`).

### Concepts

- **`EventSource` can't POST**, so the stream is read by hand: `response.body` → `TextDecoderStream` →
  `EventSourceParserStream`. A bonus: `fetch` never reconnects, while an `EventSource` would restart the agent.
- **The SSE event name is the discriminator.** harness keeps `type` out of `data`; the client puts it back, and
  the generated union narrows on it.
- **A dev proxy instead of CORS.** The browser sees one origin; prod will do the same with a reverse proxy.
- **Functional state updates in a long `async` loop**: the closure holds the render it started in, so
  `setExchanges(all => …)` instead of reading `exchanges`.
- **Tailwind 4 is configured in CSS.** `@theme` variables become utilities; `--color-*: initial` removes the
  built-in palette, so only the tokens exist.

### How to verify

```bash
npm ci --prefix services/webapp    # once, for make test / make lint on the host
make test && make lint
make up                            # restart it: the webapp service is new
open http://localhost:8080
```

1. "Can we fully reserve order 1003? Just check." → "Working…", then the answer streams in; Send stays disabled
   until it ends. Type the next question meanwhile: it waits in the box.
2. Stop harness (`docker compose stop harness`), send → "Request failed (502)", Send comes back.
3. Change `--color-accent` in `src/index.css` → the button changes color without a reload.

Smoke run before review, against `make up`'s harness with the webapp image in a throwaway container on the same
network:

- SSE through the Vite proxy arrives frame by frame (`text` came 1.3 s after `tool_result`), not buffered.
- Headless Chrome, order 1003: 14 s of "Working…" (reasoning and tools aren't shown yet), then the answer; Send
  enabled on `done` at 18.1 s. The interim "I'll check order 1003…" and the answer run together (`…changes.No —`),
  and Markdown shows as raw pipes: both are 010.2.
- A webapp pointed at a dead harness: the proxy answers 502, the reply says "Request failed (502)".
- `docker cp` of an edited `index.css` into the container → `[vite] hmr update /src/index.css`.
- Light and dark themes both read well.

### Debrief: takeaways

Opus review of the staged diff. Fixed after review:

- **A harness that died mid-stream locked the composer forever.** Vite's proxy pipes the response and only answers
  502 before the first byte; after it, an upstream death never ends the browser's response. Reproduced against
  our `vite.config.ts` (an upstream that sends one frame and drops the socket: still hanging after 5 s); now
  `configure` destroys the response when the upstream one closes incomplete, and the stream ends in ~320 ms →
  "Connection lost". A client-side idle watchdog went to the backlog.
- **`streamChat` didn't cancel its reader on an early exit** (a parse error, a consumer's `break`), leaving the
  connection and the agent run open: `finally { reader.cancel() }`.
- **Unexpected errors hid behind "Connection lost"**: non-`HttpError`s go to `console.error` too.
- **oxlint warnings didn't fail `make lint`** (every default rule is a warning): `--deny-warnings`.
- `color-scheme: light dark`, so scrollbars and form controls follow the dark theme; `wrap-break-word` on
  messages; the proxy matches `/api/`, not `/apiary`; tests for tool events and a UTF-8 character split across
  chunks (10 tests); comment and doc fixes.

Found along the way:


- TypeScript 6 turns `strict` on by default, which is why the `create-vite` tsconfig doesn't mention it.
- `create-vite` 9 ships oxlint, not ESLint.
- `openapi-typescript` 7.13 still declares `typescript@^5` as a peer, so it runs through `npx` instead of
  living in `devDependencies`.
- `ReadableStream` async iteration isn't in every browser yet; `streamChat` uses a reader loop.
